### B. Definitions (Defs.lean) — key reasoning

**Palt / altSeqVal**: `Palt a := SimpleGraph.fromRel (fun x y => ∃ i, i+1<a ∧ x=altSeqVal a i ∧ y=altSeqVal a (i+1))`. Confirmed mathlib's `SimpleGraph.fromRel r` has `Adj a b := a≠b ∧ (r a b ∨ r b a)` (read directly from `Mathlib/Combinatorics/SimpleGraph/Basic.lean:132`) — i.e. it symmetrizes the directed "consecutive pair" relation into an undirected edge set, exactly matching "the a−1 edges are the consecutive pairs of the sequence." Hand-checked against statement.md's own a=4 example (sequence (0,3,1,2), edges {0,3},{3,1},{1,2)) — matches term-for-term.

**Dih generators**: Read mathlib source directly (not just docstrings). `Mathlib/Logic/Equiv/Fin/Rotate.lean:68`: `theorem finRotate_apply (i : Fin n) : finRotate n i = i + 1`. `Mathlib/Data/Fin/Rev.lean` module doc: "`Fin.rev : Fin n → Fin n` which maps `i` to `n - 1 - i`"; `revPerm` docstring: "the antitone involution ... `i ↦ n-(i+1)`" (same value). Both match statement.md line 15 exactly. The project's own `rho_symm_shift`/`sigma_cast` lemmas independently pin these facts via machine-checked proofs (`finRotate_apply`, `Fin.val_rev`), which only typecheck because the underlying mathlib definitions are what the docs claim — a second, independent confirmation beyond reading the doc comments.

**actGraph**: Read mathlib's `SimpleGraph.comap` directly (`Mathlib/Combinatorics/SimpleGraph/Maps.lean:129-130`): `Adj u v := G.Adj (f u) (f v)`. With `f = γ.symm`, this gives `(actGraph γ H).Adj (γ i) (γ j) ↔ H.Adj (γ.symm (γ i)) (γ.symm (γ j)) ↔ H.Adj i j`, i.e. edge set `{{γ(i),γ(j)} : {i,j}∈E(H)}` — statement.md line 22's γ(H) exactly.

**GammaCopy vs statement.md's two forms**: statement.md gives (1) the `(v,γ)`-pair definition and (2) the equivalent "some H′ in the orbit admits a monotone embedding" form. Lean's `GammaCopy` encodes form (1) directly and verbatim (`∃ v γ, γ∈Γ ∧ ∀ i j, H.Adj i j → target.Adj (v(γ i))(v(γ j))`), using `Fin m ↪o Fin n` (mathlib `OrderEmbedding`) for "increasing map." It is one of the two stated-equivalent forms, encoded exactly — not a third, different formulation.

**Rdih / one-graph-two-colors**: `Rdih := sInf {n | ∀ G : SimpleGraph (Fin n), GammaCopy H1 (Dih m1) G ∨ GammaCopy H2 (Dih m2) Gᶜ}`. Every 2-coloring of `E(K_n)` corresponds to exactly one `G` (its color-1 edge set) and vice versa (color 2 = `Gᶜ`), so quantifying `∀ G : SimpleGraph (Fin n)` is a genuine bijection with "every 2-coloring," not a restriction. `Nat.sInf` of an empty set defaulting to `0` is standard mathlib convention; it degenerates safely (the definition just returns a wrong/junk value `0` if no valid `n` exists) and is not itself a correctness claim — existence is the *proof's* job, out of scope here per "not a proof audit," but the definition does not silently misstate the quantifier structure either way.

**Mgraph / Hgraph vs candidate-proof.md Part 0**: `c : ZMod a` directly models "c ∈ Z/aZ" (idiomatic Lean choice, not a manual-mod workaround). `Hgraph a c := Mgraph a c ⊔ Mgraph a (c+1)` — `c+1` is `ZMod a` addition, i.e. already "mod a," matching `M_{c+1 mod a}`. Confirmed via the project's own machine-checked `hgraph_adj_iff`. No index-convention drift found.

### C. The four proved theorems vs paper lemmas

1. **`palt_eq_Hgraph`** (`3 ≤ a`): `Palt a = Hgraph a (↑(a-1))`. Matches Lemma 0.1 ("For a≥3, P_a^alt = H_{a-1}") exactly, same hypothesis, same claim (graph equality, not isomorphism).

2. **`actGraph_rho_hgraph`** (`2 ≤ a`): `actGraph (rhoPerm a) (Hgraph a c) = Hgraph a (c+2)`. Matches Part 0's "ρ(H_c)=H_{c+2}" exactly.

3. **`actGraph_sigma_hgraph`** (no hypothesis): `actGraph (sigmaPerm a) (Hgraph a c) = Hgraph a (-3-c)`. Matches Part 0's "σ(H_c)=H_{-3-c}" exactly.

4. **`realizes_palt_succ_iff`** (`1 ≤ q`, i.e. `p=q+1≥2`) vs **Lemma 3.1**: this is the one requiring genuine judgment.

   Lemma 3.1 states an *edge-set decomposition* of `P_p^alt`: rank 0 has degree exactly 1 (unique edge to rank p−1), and the rest of the graph, relabeled, is exactly `mirror(P_{p-1}^alt)`. Since rank 0's edges are *exactly* the one edge (not "at least"), this is a complete, two-part enumeration of all of `P_p^alt`'s edges: `{0,p-1}` plus the relabeled `mirror(P_{p-1}^alt)` edges, nothing more.

   `realizes_palt_succ_iff` states, for an arbitrary map `v : Fin(q+1) → Fin n` into an ambient `G`: "`v` realizes `P_{q+1}^alt` in `G`" ↔ "`v 0 ~_G v(last)`" ∧ "`v∘succ` realizes `mirror(P_q^alt)` in `G`." This is a direct, mechanical unwinding of the edge-set decomposition above (an "∀ edge in `A∪B`, φ(edge)" statement splits into "∀ edge in A, φ" ∧ "∀ edge in B, φ" by pure logic) — **and its Lean proof confirms this**: it goes through `palt_adj_iff`/`hmirror` (index-sum characterizations) with no use of `v`'s injectivity or monotonicity anywhere. So generalizing `v` from an "increasing tuple" (the paper's context) to an arbitrary function is a harmless, unused generalization of the carrier, not a change to the mathematical content.

   Crucially, this is not an ad hoc reformulation invented for this audit to judge: **the paper's own Lemma 4.1 proof invokes Lemma 3.1 in exactly this pointwise-iff shape** ("a (q+1)-tuple ... realizes P_{q+1}^alt if and only if l ~_G r_{q-1} ... AND the map j -> r_{j-1} ... realizes mirror(P_q^alt)"). So calling `realizes_palt_succ_iff` "Lemma 3.1 in an equivalent pointwise form" is **honest** — it is the same fact, in the same shape the paper itself later needs it in, not a weaker or stronger claim.

No theorem carries a hypothesis *stronger* than what the paper needs; the two differences found are generalizations, not restrictions, so none threaten the intended `a≥4` (hence `a≥3`, `p≥2`) use.

## Overall verdict

**FAITHFUL-WITH-NOTES.** No deviations found. Notes (none blocking): (1) `Nat.sInf ∅ = 0` in `Rdih` is a standard degenerate-default convention whose soundness depends on an existence proof out of this audit's scope; (2) `realizes_palt_succ_iff` generalizes Lemma 3.1's carrier from increasing tuples to arbitrary maps, harmlessly and unused; (3) `altSeqVal_lt` is unused dead code, covered by the hygiene grep regardless.
